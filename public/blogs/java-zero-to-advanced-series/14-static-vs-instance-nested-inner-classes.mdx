## Static Members Belong to the Class, Not the Object

A `static` field or method belongs to the class itself — one shared copy exists regardless of how many (or how few) instances are created.

```java
public class Counter {
    private static int totalInstances = 0;   // shared across ALL Counter objects
    private int id;

    public Counter() {
        totalInstances++;
        id = totalInstances;
    }

    public static int getTotalInstances() {   // static method — no "this", can't access instance fields
        return totalInstances;
    }
}
```

```java
new Counter();
new Counter();
System.out.println(Counter.getTotalInstances());   // 2 — called on the class, not an instance
```

A static method has no implicit `this` and therefore cannot directly access instance fields or call instance methods — it only has access to other static members.

## Static Initialization Blocks

Run once, when the class is first loaded by the JVM — before any instance is created and before `main()` in some cases, depending on which class triggers loading first.

```java
public class Config {
    private static final Map<String, String> SETTINGS;

    static {
        SETTINGS = new HashMap<>();
        SETTINGS.put("env", "production");
        SETTINGS.put("region", "ap-south-1");
    }
}
```

This is the standard way to perform complex static field initialization that can't be expressed as a single field-initializer expression.

## The Four Kinds of Nested Classes

### 1. Static Nested Class

Declared with `static` inside another class — behaves like a top-level class that happens to be namespaced inside another, with **no implicit reference** to an enclosing instance.

```java
public class Outer {
    static class Node {         // static nested class
        int value;
        Node(int value) { this.value = value; }
    }
}

Outer.Node node = new Outer.Node(5);   // no Outer instance needed
```

This is exactly the pattern used for helper types like a linked list's internal `Node` class.

### 2. Inner Class (Non-Static)

Declared without `static` — each instance is implicitly tied to an enclosing `Outer` instance, and can access that outer instance's fields directly, including private ones.

```java
public class Outer {
    private int outerValue = 10;

    class Inner {                       // non-static inner class
        void show() {
            System.out.println(outerValue);   // direct access to Outer's private field
        }
    }
}

Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();   // requires an existing Outer instance
inner.show();   // 10
```

### 3. Local Class

Declared **inside a method body** — scoped entirely to that method, useful for small helper logic that's genuinely only relevant to one method.

```java
public void process() {
    class Helper {                     // local class — only visible inside process()
        void assist() { System.out.println("helping"); }
    }
    new Helper().assist();
}
```

### 4. Anonymous Class

A class with no name, declared and instantiated in a single expression — commonly used to implement an interface or extend a class on the spot for a one-off use.

```java
Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running anonymous task");
    }
};

Button button = new Button();
button.setOnClickListener(new ClickListener() {
    @Override
    public void onClick() {
        System.out.println("Clicked!");
    }
});
```

Anonymous classes were the standard way to implement single-method callback interfaces before Java 8 lambdas (Chapter 31) offered a much terser syntax for the same functional-interface use case.

## Choosing Between Them

| Type | Needs enclosing instance? | Typical use |
|---|---|---|
| Static nested | No | Helper/data types logically grouped with the outer class (e.g., `Map.Entry`) |
| Inner (non-static) | Yes | Needs deep access to an enclosing instance's state (e.g., an `Iterator` implementation tied to its collection) |
| Local | Yes (if non-static method) | One-off logic scoped to a single method |
| Anonymous | Yes (if non-static context) | One-off implementation of an interface/abstract class, superseded by lambdas for functional interfaces |

## Key Takeaways

- Static members belong to the class and are shared; instance members belong to each object separately.
- A static method has no `this` and cannot access instance members directly.
- Static nested classes don't need an enclosing instance; non-static inner classes do, and can access the outer instance's private state.
- Anonymous classes are largely superseded by lambdas for functional interfaces, but remain useful for implementing multi-method interfaces or abstract classes inline.

## Interview Questions

**1. What's the fundamental difference between a static member and an instance member?**
A static member belongs to the class itself — exactly one copy exists in the JVM regardless of how many instances exist, and it's accessible without creating any object. An instance member belongs to each individual object, with a separate copy per instance, and requires an object reference to access.

**2. Why can't a static method access instance fields or call instance methods directly?**
A static method has no implicit `this` reference, because it's not associated with any particular object — it can be called (`ClassName.method()`) without any instance existing at all. Since instance fields and methods only make sense in the context of a specific object, there's nothing for the static method to resolve them against.

**3. When does a static initialization block run, and how many times?**
It runs exactly once, when the JVM first loads the class (triggered by the first active use of the class — instantiating it, accessing a static member, etc.), before any instance of the class is created. It never runs again for that class within the same JVM instance's lifetime, regardless of how many objects are subsequently created.

**4. What's the key structural difference between a static nested class and a non-static inner class?**
A static nested class has no implicit reference to an instance of its enclosing class — it can be instantiated independently, just needing the enclosing class name as a namespace (`Outer.NestedClass`). A non-static inner class holds an implicit reference to the specific enclosing instance it was created from, requires that enclosing instance to exist first (`outer.new Inner()`), and can directly access that instance's fields, including private ones.

**5. Why does creating an inner (non-static) class instance require syntax like `outer.new Inner()`?**
Because every non-static inner class instance is intrinsically tied to a specific enclosing instance — the JVM needs to know *which* `Outer` instance's state the new `Inner` instance should be able to reach. Without an existing `Outer` object to anchor it to, there's no enclosing state for the inner class to hold a reference to.

**6. What is a local class, and what can it access from its enclosing method?**
A local class is defined directly inside a method body, visible only within that method. It can access the enclosing method's local variables and parameters, but only if they are effectively final (never reassigned after initialization) — this restriction exists because the local class instance can outlive the method call itself, so the compiler captures a copy of those variables' values rather than a live reference to the stack frame.

**7. What is an anonymous class, and why were they heavily used before Java 8?**
An anonymous class is a class with no declared name, defined and instantiated in a single expression, typically to provide a one-off implementation of an interface or to extend a class for a single specific use. Before Java 8 introduced lambda expressions, anonymous classes were the standard (if verbose) way to implement single-method callback interfaces like `Runnable`, `Comparator`, or GUI event listeners inline.

**8. Can an anonymous class have a constructor of its own?**
No — since it has no name, it cannot declare an explicit named constructor. It can, however, use an instance initializer block for setup logic, and if extending a class, it implicitly invokes that superclass's constructor with whatever arguments are passed in the anonymous class expression itself.

**9. Why do lambdas largely replace anonymous classes for functional interfaces, but not entirely replace them?**
Lambdas provide a much more concise syntax specifically for implementing an interface with exactly one abstract method, and they don't carry the overhead of `this` referring to a separate anonymous class instance. However, lambdas can't be used to implement interfaces or abstract classes with more than one abstract method, and can't add extra fields or helper methods of their own — for those cases, an anonymous (or named) class is still required.

**10. Does a static nested class have access to the enclosing class's private instance fields?**
No — since a static nested class has no implicit reference to any enclosing instance, it cannot directly access instance-level members of the outer class at all. It can, however, access the outer class's `static` members freely, since those don't require any particular instance.

**11. What's a practical real-world example of when a non-static inner class is the right choice over a static nested class?**
A custom `Iterator` implementation for a collection class often needs direct, ongoing access to the specific collection instance's internal state (like the current position and the backing array/nodes) as iteration progresses — implementing it as a non-static inner class gives it that implicit, automatic access to the enclosing collection instance without needing to explicitly pass a reference into a constructor.

**12. What happens to a local or anonymous class's captured local variables if the enclosing method returns before the class instance is used?**
The instance continues to work correctly using its own captured copies of those effectively-final local variables — the JVM stores copies of the values inside the class instance itself at creation time, so the instance doesn't depend on the enclosing method's stack frame still existing, even though that stack frame is popped once the method returns.

**13. Why must local variables captured by a local or anonymous class be "effectively final"?**
Because the class instance may be used after the enclosing method has already returned and its stack frame destroyed, the compiler captures a snapshot copy of each referenced local variable's value at the point of class creation rather than a live reference to the original stack variable. If the variable could be reassigned after that snapshot was taken, the captured copy and the "real" variable could silently diverge, so Java forbids capturing any variable that isn't guaranteed to remain unchanged after initialization.
