## Installing a JDK

For this series, install a **JDK 21 (LTS)** distribution. Any of these work identically for our purposes:

- Eclipse Temurin
- Amazon Corretto
- Oracle OpenJDK

After installation, verify it from a terminal:

```bash
java -version
javac -version
```

Both should report `21` (e.g. `openjdk version "21.0.x"`). If `java` works but `javac` doesn't, you've likely installed a JRE-only distribution — grab the full JDK instead.

## IDE Options

You don't need an IDE to learn Java, but one makes life easier once programs grow beyond a few files:

- **IntelliJ IDEA (Community Edition)** — most widely used for Java/Spring Boot work; this is what we'll assume for later Spring Boot chapters.
- **VS Code** with the "Extension Pack for Java" — lightweight, good for following along with this series.
- **Eclipse** — long-standing, less common for greenfield projects today but still widely used in legacy enterprise shops.

## Compiling and Running from the Command Line

Understanding the raw `javac`/`java` workflow matters even if you'll use an IDE day-to-day, because it's what the IDE is doing under the hood — and it's what CI pipelines and Dockerfiles do directly.

```java
// HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

```bash
javac HelloWorld.java   # produces HelloWorld.class
java HelloWorld         # runs it — note: no .class extension here
```

Since Java 11, for single-file programs you can skip the explicit compile step entirely:

```bash
java HelloWorld.java
```

This compiles in-memory and runs immediately — convenient for quick scripts and scratch files, though real projects still compile explicitly via Maven/Gradle.

## Anatomy of Hello World

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

- `public class HelloWorld` — declares a class named `HelloWorld`. The **file name must match the public class name exactly** (`HelloWorld.java`), or the compiler rejects it.
- `public static void main(String[] args)` — the entry point the JVM looks for by exact signature. `public` (JVM can call it externally), `static` (no object instantiation needed), `void` (no return value), `String[] args` (command-line arguments).
- `System.out.println(...)` — `System.out` is a pre-configured `PrintStream` pointing at standard output; `println` writes the argument followed by a newline.

### Passing Command-Line Arguments

```java
public class Greet {
    public static void main(String[] args) {
        if (args.length > 0) {
            System.out.println("Hello, " + args[0] + "!");
        } else {
            System.out.println("Hello, stranger!");
        }
    }
}
```

```bash
java Greet Rahul   # -> Hello, Rahul!
java Greet         # -> Hello, stranger!
```

## Common Beginner Errors

- **`Error: Could not find or load main class`** — usually a mismatch between the compiled class's package/name and what you're telling `java` to run, or running from the wrong directory relative to the `.class` file.
- **`Error: Main method not found in class X`** — the signature doesn't match exactly (e.g., missing `static`, wrong casing, or missing `String[] args`).
- **File/class name mismatch** — a public class `Foo` must live in `Foo.java`, not `foo.java` or `Main.java`.

## Key Takeaways

- A JDK (not just a JRE) is required for development — it includes `javac`.
- The public class name and the file name must match exactly.
- `java SomeFile.java` (Java 11+) lets you skip explicit compilation for quick single-file programs.

## Interview Questions

**1. What's the exact signature the JVM looks for as a program's entry point, and why does each keyword matter?**
`public static void main(String[] args)`. `public` allows the JVM (external caller) to invoke it; `static` allows invocation without creating an instance first; `void` because it doesn't return a value to the caller; `String[] args` receives command-line arguments. Changing any part of this signature (e.g., making it non-static, or naming the parameter array differently doesn't matter, but changing its type does) means the JVM won't recognize it as the entry point.

**2. Why must the public class name match the file name in Java?**
The compiler enforces this so that when a class is referenced from elsewhere (including by the JVM's class loader, which looks for `ClassName.class` files), the file system location is predictable. Non-public classes in the same file don't have this restriction — a file can contain multiple classes, but at most one public class matching the file name.

**3. What happens if you compile a file with multiple classes in it?**
`javac` compiles each top-level class (public or package-private) into its own `.class` file, regardless of how many classes are defined in a single `.java` source file. Only one of them may be `public`, and it must match the file name.

**4. What's the difference between `java HelloWorld` and `java HelloWorld.java` (Java 11+)?**
`java HelloWorld` runs a previously-compiled `HelloWorld.class` file that must already exist on the classpath. `java HelloWorld.java` (the single-file source-launch feature introduced in JEP 330) compiles the source in-memory and runs it immediately in one step, without producing a persisted `.class` file — convenient for scripts, not used for real multi-file projects.

**5. How does the JVM find the class you're asking it to run?**
It searches the classpath — by default, the current directory, plus any directories or JARs explicitly specified via the `-cp`/`-classpath` flag or the `CLASSPATH` environment variable — for a `.class` file matching the fully-qualified class name (including package).

**6. What's the difference between `System.out.println()`, `System.out.print()`, and `System.out.printf()`?**
`println` writes the argument and appends a platform-specific newline. `print` writes without a trailing newline. `printf` allows C-style format strings (e.g., `%d`, `%s`, `%.2f`) for structured output without manual string concatenation.

**7. What is `args` in `main(String[] args)`, and what happens if no arguments are passed?**
It's an array of the command-line arguments passed after the class name when invoking `java`. If none are passed, `args` is an empty array (`args.length == 0`) — not `null` — so checking `args.length` is safe without a null check.

**8. Why might `javac` succeed but `java` fail with "Could not find or load main class"?**
Common causes: running `java` from a different working directory than where the `.class` file lives (and the classpath doesn't account for that), a package declaration mismatch (if the source declares `package com.example;`, the compiled class must be invoked as `java com.example.ClassName` from the parent of `com`), or a typo in the class name passed to `java`.

**9. Can a Java source file have zero public classes?**
Yes — a file can contain only package-private (no modifier) classes, as long as none of them is declared `public`. In that case, the file name doesn't need to match any particular class name, though convention still favors clarity.

**10. What's the practical difference between using an IDE and the raw `javac`/`java` command line for larger projects?**
IDEs (and build tools like Maven/Gradle, which we'll use going forward) manage classpath construction, dependency resolution, incremental compilation, and packaging automatically. Raw `javac`/`java` works fine for single-file learning exercises, but doesn't scale to multi-module projects with external dependencies — that's exactly the gap Maven fills, which we cover in Chapter 61.
