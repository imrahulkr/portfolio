## Arrays Are Fixed-Size, Reference-Type Objects

An array in Java is itself an object on the heap — even an array of primitives — with a fixed length set at creation time that can never change.

```java
int[] scores = new int[5];           // all elements default to 0
int[] preset = {90, 85, 77, 60, 95}; // array literal
String[] names = new String[3];      // all elements default to null
```

`scores.length` is a **field**, not a method — no parentheses, unlike `String.length()`.

## 2D and Jagged Arrays

A 2D array in Java is really an array of arrays, which means each row can have a different length — a "jagged" array.

```java
// Rectangular 2D array
int[][] grid = new int[3][4];   // 3 rows, 4 columns each

// Jagged array — rows of different lengths
int[][] jagged = new int[3][];
jagged[0] = new int[]{1, 2};
jagged[1] = new int[]{1, 2, 3, 4};
jagged[2] = new int[]{1};

for (int[] row : jagged) {
    for (int value : row) {
        System.out.print(value + " ");
    }
}
```

## The `Arrays` Utility Class

`java.util.Arrays` provides static helpers you'll use constantly instead of hand-writing loops:

```java
import java.util.Arrays;

int[] nums = {5, 3, 8, 1};

Arrays.sort(nums);                          // in-place sort: [1, 3, 5, 8]
int index = Arrays.binarySearch(nums, 5);   // requires sorted array first
int[] copy = Arrays.copyOf(nums, 6);        // pads with 0s: [1,3,5,8,0,0]
int[] range = Arrays.copyOfRange(nums, 1, 3); // [3, 5]
Arrays.fill(nums, 0);                       // fills every element with 0
boolean equal = Arrays.equals(nums, copy);  // element-wise comparison
System.out.println(Arrays.toString(nums));  // readable string form
```

Note: `System.out.println(nums)` directly (without `Arrays.toString`) prints something like `[I@1b6d3586` — the array's default `Object.toString()`, since arrays don't override `toString()`.

## Arrays vs. `ArrayList` — a Preview

```java
int[] fixedArray = new int[5];        // fixed size, primitives allowed, no resizing
List<Integer> flexibleList = new ArrayList<>();  // grows dynamically, boxed types only
```

Arrays are faster and more memory-efficient for fixed-size primitive data. `ArrayList` (Chapter 19) trades some of that efficiency for dynamic resizing and a much richer API. Choosing between them is a running theme once we reach the Collections Framework.

## Common Pitfalls

- **`ArrayIndexOutOfBoundsException`** — accessing an index `< 0` or `>= length`. Java always bounds-checks array access at runtime; there's no way to silently read out-of-bounds memory like in C.
- **Reference semantics** — assigning one array variable to another copies the *reference*, not the contents:

```java
int[] a = {1, 2, 3};
int[] b = a;        // b points to the SAME array as a
b[0] = 99;
System.out.println(a[0]);   // 99 — a is affected too!
```

To actually copy contents, use `Arrays.copyOf()`, `clone()`, or `System.arraycopy()`.

## Key Takeaways

- Arrays have a fixed length set at creation and are always objects, even for primitives.
- Multi-dimensional arrays in Java are arrays of arrays, so jagged (uneven row length) arrays are fully supported.
- `Arrays.sort`, `binarySearch`, `copyOf`, and `toString` cover the vast majority of everyday array work.
- Array variables hold references — assignment copies the pointer, not the data.

## Interview Questions

**1. Is an array a primitive type or an object in Java, even an array of `int`s?**
It's always an object, allocated on the heap, regardless of whether its elements are primitives or references. This is why arrays have a `.length` field and can be assigned to variables of type `Object`, and why `int[]` and `Integer[]` are both reference types even though `int` itself is a primitive.

**2. Why is `arr.length` accessed without parentheses, while `str.length()` on a `String` requires them?**
`length` on an array is a public final field baked into the array object itself by the JVM, not a method — arrays are a special-cased construct in the language, not regular classes with methods you could override. `String.length()` is a genuine method defined on the `String` class, following normal object-oriented method-call syntax.

**3. What's a jagged array, and how do you create one in Java?**
A jagged array is a multi-dimensional array where inner arrays (rows) can have different lengths, because a 2D array in Java is actually an array of array references, not a single contiguous rectangular block. You create one by first declaring the outer array with only the first dimension size (`new int[3][]`), then assigning each row individually with its own length (`arr[0] = new int[]{1,2};`).

**4. What happens when you print an array directly with `System.out.println(myArray)` instead of `Arrays.toString(myArray)`?**
Arrays don't override `Object.toString()`, so you get the default representation: the array's runtime type descriptor followed by its hash code in hex, like `[I@1b6d3586` (`[I` meaning "array of int"). `Arrays.toString()` (or `Arrays.deepToString()` for nested arrays) is needed to print human-readable contents.

**5. What exception is thrown when accessing an array index that's negative or `>=` its length, and when is it detected?**
`ArrayIndexOutOfBoundsException`, thrown at runtime the moment the invalid access occurs — Java always performs bounds checking on array access, unlike languages such as C that allow undefined-behavior out-of-bounds reads/writes.

**6. If you assign one array variable to another (`int[] b = a;`) and then modify `b`, does `a` change too? Why?**
Yes. Array variables hold references, not the array's contents directly, so `b = a` makes both variables point to the exact same array object on the heap. Modifying an element through `b` is modifying the same underlying data that `a` also points to. To get an independent copy, you must explicitly copy the contents (`Arrays.copyOf`, `clone()`, or `System.arraycopy`).

**7. What's the difference between `Arrays.copyOf()` and `System.arraycopy()`?**
`Arrays.copyOf(original, newLength)` creates and returns a brand-new array of the specified length, copying elements from the original (padding with default values or truncating as needed) — it's convenient but does allocate a new array internally. `System.arraycopy(src, srcPos, dest, destPos, length)` copies elements into an already-existing destination array you provide, offering more control and avoiding an extra allocation when you're managing the destination array's lifecycle yourself. `Arrays.copyOf` actually calls `System.arraycopy` internally after allocating the new array.

**8. Can you resize a Java array after it's created?**
No — array length is fixed at creation time and cannot be changed. "Resizing" in practice means creating a new, larger (or smaller) array and copying the relevant elements over, which is exactly what `ArrayList` does internally when it grows beyond its current backing array's capacity (covered in Chapter 19).

**9. What does `Arrays.binarySearch()` require of its input, and what happens if that requirement is violated?**
The array must already be sorted in ascending order for binary search's divide-and-conquer logic to be valid. If called on an unsorted array, the method's behavior is undefined/unpredictable — it may return an incorrect index or a wrong "not found" result, since it will still execute mechanically without checking the sort precondition.

**10. What's the difference between `Arrays.equals()` and `Arrays.deepEquals()`?**
`Arrays.equals()` compares two arrays element-by-element using each element's own `equals()`, but for nested arrays (an array of arrays), the inner arrays are compared by reference, not content, since an array's own default `equals()` is reference equality. `Arrays.deepEquals()` recursively compares nested array contents, which is what you want when comparing 2D or jagged arrays for structural equality.

**11. Why might you choose a fixed-size array over an `ArrayList` in performance-sensitive code?**
Arrays of primitives avoid the boxing overhead and per-element object header that `ArrayList<Integer>` incurs (since `ArrayList` can only hold reference types), and they avoid the amortized resizing/copying cost `ArrayList` pays as it grows. When the size is known upfront and the type is primitive, a raw array is typically faster and more memory-efficient.

**12. How would you make a defensive copy of an array passed into a constructor, and why would you do that?**
Use `array.clone()` or `Arrays.copyOf(array, array.length)` to store an independent copy inside the constructor, rather than storing the reference the caller passed in directly. This protects the object's internal state from being mutated later if the caller retains a reference to the original array and modifies it after construction — a common encapsulation best practice covered further in Chapter 9.
