## Categories of Operators

Java groups operators into families based on what they act on:

- **Arithmetic**: `+ - * / %`
- **Relational**: `== != > < >= <=`
- **Logical**: `&& || !`
- **Bitwise**: `& | ^ ~ << >> >>>`
- **Assignment**: `= += -= *= /= %=` and bitwise compound forms
- **Ternary (conditional)**: `condition ? valueIfTrue : valueIfFalse`
- **`instanceof`**: type-checks a reference at runtime

## Arithmetic Operators & Integer Division

```java
int a = 7, b = 2;
System.out.println(a / b);   // 1 — integer division truncates
System.out.println(a % b);   // 1 — remainder
System.out.println((double) a / b);  // 3.5 — cast forces floating-point division
```

The `%` (modulo) operator also works on floating-point types in Java, unlike some languages: `5.5 % 2` yields `1.5`.

## Relational & Logical Operators, and Short-Circuit Evaluation

`&&` and `||` are **short-circuit**: the right-hand operand is only evaluated if necessary.

```java
public boolean isSafeToDivide(int numerator, int denominator) {
    return denominator != 0 && (numerator / denominator) > 10;
}
```

If `denominator == 0`, the right side (`numerator / denominator`) is never evaluated, avoiding an `ArithmeticException`. The non-short-circuit equivalents `&` and `|` also work on booleans but always evaluate both sides — useful only when the right side has side effects you deliberately want to always execute.

## Bitwise Operators

```java
int flags = 0b0101;          // binary literal (Java 7+)
int mask  = 0b0011;

System.out.println(flags & mask);   // 0001 -> 1  (AND)
System.out.println(flags | mask);   // 0111 -> 7  (OR)
System.out.println(flags ^ mask);   // 0110 -> 6  (XOR)
System.out.println(~flags);         // bitwise complement (inverts all bits)

System.out.println(-8 >> 1);        // -4  — arithmetic shift, preserves sign
System.out.println(-8 >>> 1);       // large positive number — logical shift, fills with 0
```

`>>` is the **signed** (arithmetic) right shift, preserving the sign bit. `>>>` is the **unsigned** (logical) right shift, always filling with zeros — this matters for negative numbers.

## The Ternary Operator

```java
int age = 20;
String category = (age >= 18) ? "adult" : "minor";
```

Equivalent to an if/else that assigns a value, but as a single expression — useful for concise assignments, best avoided when nested more than one level deep since it hurts readability.

## `instanceof` and Pattern Matching (Java 16+)

```java
Object obj = "hello";

// Traditional form
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// Pattern matching form (Java 16+) — cast is implicit
if (obj instanceof String s) {
    System.out.println(s.length());
}
```

The pattern-matching form eliminates the redundant explicit cast, and `s` is only in scope where the compiler can prove the check succeeded.

## Operator Precedence

From highest to lowest (abbreviated — full table in the JLS): postfix (`++`/`--`) → unary (`! ~ + -`) → multiplicative (`* / %`) → additive (`+ -`) → shift → relational → equality → bitwise AND/XOR/OR → logical AND/OR → ternary → assignment.

```java
int result = 2 + 3 * 4;     // 14, not 20 — multiplication binds tighter
boolean check = 5 > 3 && 2 < 4;   // true — relational binds tighter than &&
```

When precedence isn't immediately obvious to a reader, prefer explicit parentheses over relying on memorized precedence rules.

## Key Takeaways

- Integer division truncates; cast to `double`/`float` explicitly when you need fractional results.
- `&&`/`||` short-circuit; `&`/`|` on booleans always evaluate both sides.
- `>>` preserves sign, `>>>` doesn't — this distinction only matters for negative numbers.
- Pattern-matching `instanceof` (Java 16+) removes the redundant explicit cast.

## Interview Questions

**1. What does `7 / 2` evaluate to in Java, and why?**
`3`, not `3.5`. When both operands of `/` are integer types, Java performs integer division and truncates any fractional part. To get a fractional result, at least one operand must be a floating-point type, e.g., `7 / 2.0` or `(double) 7 / 2`.

**2. What's the difference between `&&`/`||` and `&`/`|` when used with boolean operands?**
`&&` and `||` are short-circuit operators — they skip evaluating the right-hand operand if the result is already determined by the left side. `&` and `|` are non-short-circuit — they always evaluate both operands, even if the left side alone determines the result. This matters when the right operand has a side effect (like a method call) or could throw (like a null check followed by dereferencing).
*Follow-up:* Give a concrete example where using `&` instead of `&&` would cause a bug. (Answer: `if (obj != null & obj.getValue() > 0)` — if `obj` is null, `&` still evaluates `obj.getValue()`, throwing a `NullPointerException`, whereas `&&` would short-circuit and skip it.)

**3. What's the difference between `>>` and `>>>`?**
`>>` is the signed/arithmetic right shift — it fills vacated high-order bits with the sign bit, preserving whether the number is positive or negative. `>>>` is the unsigned/logical right shift — it always fills vacated bits with zero, regardless of sign, which effectively turns a negative number into a large positive one.

**4. What does the modulo operator (`%`) do with negative operands in Java?**
The result takes the sign of the dividend (left operand), not the divisor. For example, `-7 % 3` yields `-1`, and `7 % -3` yields `1`. This differs from some languages (like Python) where modulo takes the sign of the divisor.

**5. Can the `%` operator be used with floating-point operands?**
Yes — unlike C, Java's `%` works on `float` and `double` as well as integer types, computing the remainder of floating-point division, e.g., `5.5 % 2.0` yields `1.5`.

**6. What is operator precedence, and why should you not rely on memorizing the full table in production code?**
Operator precedence determines the order operators are evaluated in an expression without explicit parentheses (e.g., multiplication before addition). While the JLS defines a complete precedence table, code that depends on a reader correctly recalling subtle precedence rules (like bitwise vs. relational operators) is harder to review and more bug-prone — explicit parentheses communicate intent directly and cost nothing at runtime.

**7. What is the pattern-matching form of `instanceof` introduced in Java 16, and what problem does it solve?**
`if (obj instanceof String s)` combines the type check and the cast into a single expression — if the check succeeds, `s` is automatically bound as a `String` in the scope where the compiler can prove the check passed, eliminating the previously-required separate explicit cast (`String s = (String) obj;`) and reducing boilerplate and the chance of a mismatched cast.

**8. What's the difference between `x++` and `++x`?**
`x++` (post-increment) returns the current value of `x` before incrementing it. `++x` (pre-increment) increments `x` first, then returns the new value. In a standalone statement they behave identically, but in an expression like `int y = x++;` versus `int y = ++x;`, the value assigned to `y` differs.

**9. Is Java's ternary operator (`condition ? a : b`) a statement or an expression, and why does that distinction matter?**
It's an expression — it evaluates to a value and can be used anywhere a value is expected (assignment, method argument, return statement), unlike an if/else which is a statement and doesn't produce a value directly. This is why `String result = (x > 0) ? "positive" : "non-positive";` is valid, while trying to do the equivalent inline with if/else is not.

**10. What happens with type promotion when the two branches of a ternary expression have different numeric types?**
Java applies numeric promotion rules to unify the result type — for example, `true ? 1 : 2.0` promotes the `int` `1` to `2.0`'s type, yielding a `double` result (`1.0`), even though the condition was true and an `int` literal was written. This can surprise developers expecting the literal `int` type to be preserved.

**11. Why is `~5` equal to `-6`, not `-5`?**
`~` is bitwise complement — it flips every bit of the two's-complement representation. Because integers are stored in two's-complement form, flipping all bits of `5` (`...0101`) produces `...1010`, which as a two's-complement signed value equals `-6` (bitwise complement of `n` is always `-(n + 1)`).
